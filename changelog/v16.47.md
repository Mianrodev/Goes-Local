# v16.47-shared — invite everyone already waiting to finish with a code

Eric, 13 Oct: people who were stuck in pending before instant verification should be prompted to verify by phone or email so they move to claimed.

## What's new

- **Admin → `/admin/verify-invites`** (full admins only).
  - GET is a dry run that lists every waiting claim and new listing as SEND or skip, with the reason. Nothing is sent.
  - POST sends the next 40, so repeat until the count is 0.
- **Who gets it:** one email per person per listing, using the `verify_backlog` template:
  - Subject: "Finish {{business}} in 30 seconds — no call needed".
  - The button "Finish in 30 seconds" goes to `/verify-business/restart` (link valid 14 days), which sends a fresh code to the business phone or email.
  - Each request is marked `[invited]`, so it is never emailed twice.
- **Skipped:**
  - duplicates of a newer request
  - already invited or already sent a code
  - looks like a test
  - already theirs
  - listing no longer on the site
  - no phone or email on the listing to send a code to
  - an existing listing with no US phone to text
- **Timing fix:** a request now records when its code was sent (`claims.decided_at`). Reminders (2h–7d) and the team hand-off (26h) count from that moment, not from the original request. Before, a weeks-old request would have gone to the team straight after its first code.
- **After the code:** everything else works as in v16.46. The right code means claimed or live, plus a "Welcome call" task. A claim on a listing someone else owns gets the 72h notice. One reminder goes out if they don't finish.

## QA

51/51 local scenarios pass (`scripts/qa/verification.cjs`). The new T17 checks:
- the dry run sends nothing;
- duplicates, no-channel rows and tests are skipped;
- a person is invited once, and never again, even with an older duplicate;
- the button sends a fresh code;
- there is no instant reminder or team hand-off afterwards.
