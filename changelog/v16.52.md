# v16.52-shared — claims and new listings finish without people; only edge cases reach the dev team

Eric, 14 Oct:
- "The sales rep cannot add a tag in GHL … let's remove the sales rep from this process."
- "Only the edge cases can have a sales rep, manually, after we get informed first and we raise it."
- "Minimal pressure on us and everything automated."

(An earlier draft of this release gave sales GHL tasks answered with tags. It was dropped before going live.)

## What happens now (`autoHourly`, every hour, before `bvHourly`)

1. **Done already → closes itself.**
   - A waiting claim or new-listing request closes when the same person already owns that business on the site (`[closed: already live and owned by this person]`).
   - Older copies of a newer request also close, as do test entries and claims on listings that are no longer on the site.
2. **Never got a code → invited automatically.**
   - This covers form fallbacks, the off switch and rate limits. It applies to requests between 30 minutes and 30 days old.
   - Each one gets the "finish in 30 seconds" email once (`verify_backlog`, the same checks as Admin → Verify invites). Up to 20 per hour.
3. **Never verified → closes after 7 days.**
   - This applies to requests that got a code or invite and are still unverified 7 days later (`expired`).
   - They get one reminder in between, as before.
   - This replaces the old "hand it to the team after 26 hours".
4. **Too many wrong codes → the attempt stops quietly.**
   - The owner sees "Let's start again", with a button back to /claim or /add.
   - Nobody is alerted (it may be someone guessing). The row expires on its own.

## Edge cases → the dev team only

- **New email "Needs a look: {business} — {what happened}"** (`admin_needs_dev`, notification kind `needs_dev`).
  - It always goes to the dev inbox (`DEFAULT_NOTIFY_EMAIL`), never to a sales list.
  - It has a link to the right admin queue. The dev team decides, and passes it to a sales rep if needed.
- **It's sent only for:**
  - The owner tapped "Can't get the code? Send it to our team".
  - There's no phone or email we can send a code to.
  - Verified, but finishing or publishing failed (a bug).
  - Ownership dispute: the current owner tapped "Keep my listing". This replaces the GHL task for the rep. The owner's page now says "We'll be in touch if we need anything from you".
- **Unchanged:** the "Welcome call" GHL task after a listing is approved or published. That's the account-manager welcome, not an approval step.

## First run on live data (from a read-only dry run)

- **Miami:** about 30 close, for the same reasons.

- **No business gets an email, and no dev alert goes out on day one.**
