## v16.37-shared — fixes from the admin QA (8 Oct)

Eric asked for a full QA of the admin panel. I opened every admin page on all three cities in a real browser, look-only: every non-GET request was blocked, and Run sync, Listing URL sync and Migrate were skipped because they act the moment they are opened. Fixes:

- **Tampa ran on the wrong side of the world.**
  - Tampa's Worker ran in New Jersey (`cf-placement: local-EWR`) while its D1 is in Singapore, so every database query took about 225 ms.
  - Effect: visitor pages took ~3 s (Miami 0.6 s), and Migrate and Hide duplicates took ~35 s (Tampa duplicates timed out with a 502).
  - Miami and Orlando were already placed next to their D1 (`remote-SIN`); Smart Placement never moved Tampa.
  - Fix: wrangler.toml pins Tampa with `placement = { region = "aws:ap-southeast-1" }`. scripts/check-live.mjs now compares placement mode *or* region.
- **Tampa's search index (`biz_fts`) did not exist.** It was created by hand on 8 Oct with the same statement `migrate()` uses, and it fills at the next sync (`fts_at` is unset).
- **Claims were saved twice.** Example: Korean Massage by Maya, two rows 2 s apart in Miami's queue. Fix:
  - The claim button locks after the first click.
  - `/api/claim` skips a second claim for the same listing and email while one is pending, approved or auto-verified within 24 h, and shows "We already have your claim".
- **/admin showed a bare developer list of 9 routes.** It (and any unknown /admin address) now redirects to Pending listings.
- **Cloudflare Web Analytics was blocked on every page.** The Content-Security-Policy refused `static.cloudflareinsights.com`, which also logged a console error on every page. Both hosts are now allowed in `script-src` and `connect-src`.

Status: live on all three cities 8 Oct 2026 (Eric approved). Tampa now answers with cf-placement: remote-SIN: pages ~1 s (was ~3 s), Hide duplicates ~2 s (was ~36 s). /admin lands on Pending listings; the claim button locks; check-live compares a pinned region as mode "targeted". Deployed with `ALLOW_CONFIG_CHANGE=1` because of the Tampa placement change.

## v16.38-shared — Google Analytics hits were being blocked

Found during the v16.37 check. GA4 sends some hits to `https://www.google.com/g/collect` (and regional `*.google-analytics.com` / `*.analytics.google.com` hosts). Our Content-Security-Policy `connect-src` didn't allow them, so browsers refused those requests ("Refused to connect … violates the Content Security Policy"), and some visits never reached Google Analytics on all three cities. `connect-src` now allows those hosts.

Status: committed, not yet deployed (waiting on Eric's go-ahead).
