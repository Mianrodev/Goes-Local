# v15.81-shared (25 Sep 2026)

Speed and crawler load. No visible change for visitors.

**Findings (docs/QA-2026-09-25.md follow-up, handoff 5b):**
- `/blog` returned 200 on 30/30 uncached requests and Observability shows no /blog exceptions in the last 7 days — but it took 1.5–2.5 s. Both D1 primaries run in **APAC (Singapore)** while visitors are in Florida, so every query from a US edge crossed the Pacific. Slow responses, not crashes, are the likely cause of Search Console's "could not fetch".
- ~90% of Worker requests in a sample hour (both cities) were crawlers walking every combination of the listing filters (`hood` × `rating` × `claim` × `sort`): mainly **Applebot** (Apple, ASN 714, several req/s) plus a scraper on Alibaba Cloud Singapore. Those pages already canonicalise to the plain category page, so they have no search value.

**Changes:**
- Smart Placement on both Workers (config only, deployed before this version): the Worker runs next to D1. Orlando /blog went from 0.7–2.5 s to ~0.5 s.
- `robots.txt`: `Disallow: /*?*rating=`, `/*?*claim=`, `/*?*sort=` in every user-agent group. `?hood=` alone and `?page=` stay crawlable.
- `/blog` and `/news` index pages select only the card fields instead of `SELECT *` (Miami's blog list was pulling ~1.6 MB of full post bodies per view). Rendered HTML verified byte-identical against v15.80 on live Miami data.
