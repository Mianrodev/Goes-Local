# v16.64-shared — one listing per Google business

Eric (21 Oct): "when the Google URL / Google CID is the same we don't need to have that repeated business on the website".

## Change
- `dedupeListings` (end of each full sync, and Admin → /admin/duplicates) now also treats listings with the same
  Google listing as one business: the CID in the Maps link (`?cid=…` or `0x…:0x…`), else the place id (`gp_id`).
- **Only when the names agree too** (same name, or one contains the other, e.g. "Walgreens" / "Walgreens Pharmacy").
  Miami has ~70 Google links shared by clearly different businesses ("Brickell Mazda" / "Honda Service & Parts
  Center", same review count) — a Google link copied onto the wrong contact. Those are left visible and listed at
  `/admin/duplicates?google` (CSV) for the team to fix in GHL.
- Same rules as the existing duplicate hiding: best copy kept (claimed → paid → most reviews), claimed/paid copies are
  never hidden, hidden copies' addresses 301 to the kept listing, nothing changes in GHL.
- Name+phone+address and Google matches are joined into one group (union-find), so a group keeps exactly one listing;
  copies hidden earlier move to the new kept listing if their old one is now hidden.

## Live impact (read-only check, 21 Oct)

- Miami mismatched Google links: 147 listings to check.
