# v16.54-shared — the claims and listings jobs run first every hour; backlog tidy

Includes v16.53 (state sites only: the app name on the home screen and in the manifest is the site brand).

## Fixed

- **The claims and new-listing jobs (`autoHourly`, `bvHourly`) now run first in the hourly cron.**
  - They run straight after the hourly marker is set, before the Google reviews, GHL URL-field, best-of index and logo-check batches.
  - On 14 Oct the 22:15 Orlando hourly run set its marker but never reached them, because the slower batches used up the run.
  - This also covers the reminders, the 72h ownership moves and the 7-day expiry, which sat in the same place.

## Backlog tidy (`autoHourly` step 1b)

- **Backlog invites from 13 Oct** were sent before `decided_at` was recorded for invites, so they could never expire. Their 7 days now start from the first run of this version.
- **Requests held back as likely spam on 13 Oct** (`[held: …]`, never invited; 26 rows across the cities) are closed as `rejected` ("held back as likely spam"). No email goes out.

## QA

- The local suite now has 74 tests, all passing.
- New T34: an old backlog invite starts its 7 days instead of expiring at once, and a held request is closed.
