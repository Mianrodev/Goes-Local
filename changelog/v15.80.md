# v15.80-shared (25 Sep 2026)

Two security fixes from the 25 Sep QA (docs/QA-2026-09-25.md). No visible change for visitors.

- **Listing takeover closed.** The claim form ("Manager"/"Other Employee") and the "List your business" form no longer write the typed owner email onto the CRM contact at submission. That email was synced into `owner_email`, which is what grants /manage access — so anyone could gain edit rights over any listing (for /add, by entering an existing listing's phone number, since the form reuses that contact). Owner email is now set only when staff approve (Admin → Claims, Admin → Pending, or the GHL status webhook), exactly as those paths already did. The typed owner details still reach staff in the notification email, the claim notes and the CRM note.
- **Script injection in pages closed.** New `SJ()` serialises JSON into inline `<script>` blocks with `<`, `>`, `&`, U+2028/2029 escaped. Used for all JSON-LD (listing, breadcrumbs, FAQ, SEO custom schema, blog/news schema), listing opening hours, and the admin category/editor data. Before, a listing name/description/hours containing `</script>` ran as code for every visitor (reproduced locally on v15.79) and broke the page's structured data.

Tested locally with `wrangler dev` against a seeded listing: hostile code ran on v15.79 and not on v15.80; JSON-LD parses on v15.80; claim and add-listing forms complete as before.
