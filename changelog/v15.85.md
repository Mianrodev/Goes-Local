# v15.85-shared (25 Sep 2026)

Cost plan Phase B — cheaper database work behind every page.

- **Indexes** (created live on both D1s on 25 Sep and added to `migrate()`): `ix_cs_hood_sub(cs,hood,sub)`, `ix_cs_sub_rank(cs,sub,premium,claimed,rat,rev)`, `ix_cs_rank(cs,premium,claimed,rat,rev)`, `ix_cs_related(cs,plus,premium,rat)`. `EXPLAIN QUERY PLAN` confirms the top queries (filter counts, sub-category listing, "related businesses", category listing) now use them with no temp sort.
- **Category/sub-category/total counts** (`shell()`): result saved in `meta` row `shell_v1` and reused by every Worker instance for 30 min (plus the 15-min in-memory copy). Any sync/admin change that used to clear the in-memory copy also sets `SHELL_DIRTY`, forcing a recompute that refreshes the saved row. Replaces three whole-table scans that ran ~14k times/day on Miami.
- **Search index**: `insertOne()` no longer runs a full FTS rebuild per listing (~2,800/day on Miami). The rebuild now only runs at the end of a sync pass, and only if a listing changed or was removed since the last rebuild (`meta.fts_at`). A brand-new listing appears in keyword search within one sync pass (~30 min); it's on its category page immediately.
- **Claim-invite job**: each waiting business is checked at most once every 6 hours (`pending_email_invites.last_checked_at`, new column). Miami had 12 waiting, re-checked every 5 minutes = ~3,500 GHL calls + upserts/day; now ≤ 48.
- **Business-page views**: no longer written server-side on every request (bots included, and cached pages wouldn't run it anyway). The page's own script sends one `view` beacon per browser tab session via the existing `/api/track`, skipping bot/headless/automated browsers.
- Sitemaps are cached for 12 h by v15.84's edge cache.

Tested locally: migrate creates the column and indexes; `shell_v1` written; invite rows get `last_checked_at` and aren't re-checked before 6 h; the view beacon is in the page.
